# FrontierOS v2：90 天实施路线

**目标：** 在 90 天内把 CreativeOS-99 从静态创意增强器升级为具有来源治理、开放式谱系、人类品味和真实执行反馈的可测系统。  
**原则：** 每阶段都有退出条件；没有证据就不宣称“前 1%”。

## 第 1–30 天：Frontier Observatory

### 要交付

1. 为所有来源记录 H0/H1/M0/M1、时间、作者、AI 参与度、原件位置和变换链；
2. 建立 30/90/365 天窗口，计算主题增速、近邻密度、来源纯度和概念饱和；
3. 把来源不明或高度合成内容放入隔离区；
4. 接入至少两种人类原生信号：访谈/现场笔记/草图/实验/失败日志；
5. 建立关系类比节点，至少覆盖三个遥远领域；
6. 原文优先：摘要可定位，结论必须可回溯到原件。

### 指标与退出条件

| 指标 | 第 30 天退出线 |
|---|---:|
| 新增核心节点可追溯率 | ≥ 95% |
| H0/H1 原件保留率 | 100% |
| M1 隔离正确率（抽检） | ≥ 95% |
| 关系类比节点 | ≥ 100 个 |
| 有 transfer/failure conditions 的类比 | ≥ 90% |
| 人类原生信号占核心新增节点 | ≥ 30% |

### 实验

- A/B：文本近邻检索 vs 功能—机制关系检索；
- 观察：候选覆盖增益、近邻风险、质量损失和跨域盲评；
- 只在关系检索至少提高一个结构簇且质量不显著下降时扩大投入。

## 第 31–60 天：Open-ended Archive

### 要交付

1. 使用 islands + MAP-Elites 或同类质量—多样性档案；
2. 每个候选记录父节点、算子、知识节点、模型配置、人类理由、拒绝原因与后代；
3. 建立七个默认生态位：可靠、高新颖、品味匹配、争议潜力、远距类比、反共识、未知异常；
4. 引入异构模型、语言、模态或工具，避免单一模型贡献垄断；
5. `interesting_uncertain` 进入专门档案并有复审时间；
6. 不设跨生态位单一总冠军；使用七维向量与 Pareto 保留。

### 指标与退出条件

| 指标 | 第 60 天退出线 |
|---|---:|
| 候选谱系字段完整率 | ≥ 95% |
| 活跃生态位 | ≥ 6/7 |
| 最大单一模型贡献份额 | < 60% |
| `interesting_uncertain` 保留率 | ≥ 90% |
| 新结构簇相对 Best-of-N 增益 | ≥ 20% |
| 近邻风险 | 不高于基线 |

### 探索预算

启发式起点：50% 已验证机制、30% 相邻前沿、20% 高风险/异常/反共识；10%–20% 候选绕过个人品味预筛。每周根据前沿扩张率和执行存活率调整，不把比例写死。

### 实验

- 普通 Best-of-N vs islands 档案；
- 单模型多 Persona vs 多谱系模型；
- 全池平均精炼 vs 多样性感知的候选子集深度精炼；
- 记录美元、时延、人类分钟、Pareto 前沿大小和后代质量。

## 第 61–90 天：Taste + Reality

### 要交付

1. 收集数百个带理由的 A/B、keep/reject/interesting-uncertain 事件；
2. 部署 TasteCore、TasteContext、TasteFrontier 三层存储；
3. 只把跨项目稳定且人确认的偏好写入 Core；
4. 用高不确定、高 Judge 分歧、高潜力样本请求人类判断；
5. 每个创作域执行一小组真实原型/发布/实验；
6. 建立 1 周、1 月、3 月反馈任务；
7. 用执行结果更新算子和知识节点价值，而不是直接奖励所有生成文本。

### 指标与退出条件

| 指标 | 第 90 天退出线 |
|---|---:|
| 带原因的可靠品味事件 | ≥ 300 |
| `interesting_uncertain` 占比 | 5%–25% |
| 品味预测校准 | 相对无校准基线显著改善 |
| 真实执行候选 | 每个优先领域 ≥ 10 |
| 1 周延迟反馈覆盖 | ≥ 80% |
| 人类每分钟杠杆 | 相对随机提问提高 ≥ 30% |
| 执行存活率 | 有基线、有置信区间，且不低于 v1 |

## 全程实验矩阵

| 组件 | 对照 | 主要指标 | 失败判定 |
|---|---|---|---|
| 来源分层 | 不分层 RAG | 来源纯度、事实错误、长尾覆盖 | 维护成本上升但无错误/覆盖改善 |
| 关系类比 | embedding 近邻 | 结构簇、新颖、可执行性 | 只提高离题度 |
| 谱系档案 | 单轮 Best-of-N | 前沿扩张、踏脚石转化 | 只增加存储，无后代价值 |
| 三层品味 | 单一 Soul/Reward | 校准、Frontier recovery | 预测更准但多样性显著下降 |
| 主动提问 | 随机人审 | 每分钟人类杠杆 | 省时但错过高价值路线 |
| 真实执行 | LLM Judge | 执行存活、延迟回忆/行为 | Judge 提升与现实无关或负相关 |
| 时间切分 | 随机切分 | 未来影响、创意半衰期 | 只记住当前流行模式 |

## 每周运行节奏

- 周一：采集 H0/H1 信号，更新前沿窗口；
- 周二：生成跨域关系与高风险探索任务；
- 周三：运行 islands，更新谱系与 Pareto 档案；
- 周四：人类只评高信息价值样本，锁定关键决定；
- 周五：制作小型原型或发布测试；
- 周末/下一周期：回写结果，复盘失败和意外后代。

## 90 天后的 Go / No-Go

只有同时满足以下条件才进入规模化：

1. 新增结构簇和 Pareto 前沿相对等预算 v1 有稳定提升；
2. 近邻风险、事实性和硬约束没有恶化；
3. 至少一个领域出现可重复的执行存活增益；
4. 人类判断时间下降或其边际价值上升；
5. `interesting_uncertain` 中出现可验证的高价值后代；
6. 新模型替换或隐藏时间窗口上仍能复现。

若不通过，保留产生真实增益的模块，回滚其余复杂度。FrontierOS 的目标不是架构华丽，而是持续获得不能由静态提示词解释的前沿增量。
