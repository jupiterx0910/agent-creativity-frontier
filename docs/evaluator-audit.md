# FrontierOS Evaluator Audit：防止搜索优化成精致的平庸

**版本：** FrontierOS v2.1  
**核心原则：** 评估器不是旁观者，而是生成搜索的目标函数。任何反复迭代的 Agent，最终都会学会迎合其循环内 Judge。

## 1. 为什么必须独立审计

LLM Judge 经常偏爱：

- 更长、更完整、更像咨询报告的答案；
- 自信、清晰、低歧义的表述；
- 熟悉的叙事模板和专业腔；
- 与自身模型家族相似的表达；
- 已被完整润色的候选，而非尚未展开但结构新颖的踏脚石。

因此，高 Judge 分不等于扩张创意前沿。多轮搜索若只优化该分数，可能提高表面质量并持续删除反共识、低保真和高潜力异常。

## 2. 四类裁判必须分离

| 裁判 | 判断对象 | 不可替代的信号 | 主要偏差 |
|---|---|---|---|
| 自动规则/检索 | 硬约束、事实、近邻、重复 | 快速淘汰明显失败 | 不理解作品价值 |
| LLM critics | 因果、结构、受众模拟、缺陷定位 | 低成本覆盖与诊断 | 风格、长度、自偏好和不稳定 |
| 人类个人/专家 | 品味、文化语境、技艺、值得性 | 价值判断和异常敏感度 | 疲劳、身份与顺序偏差 |
| 现实执行 | 行为、记忆、市场、原型、实验 | 最终外部效度 | 慢、噪声大、归因困难 |

四类结果分别保存，禁止直接平均成一个 Reward。

## 3. 最小审计集

为每个创作域建立至少 40 组对抗候选，每组只改变一种属性：

- 长 vs 短，但核心思想相同；
- polished vs low-fidelity，但结构相同；
- 熟悉模板 vs 陌生结构，但完成度相近；
- 自信语气 vs 保留意见；
- 多细节但低新颖 vs 简洁但高结构新颖；
- 同模型风格 vs 异模型/跨语言风格；
- 当前共识 vs 有证据的反共识；
- 真实引用 vs 无来源但听起来专业。

审计样本不进入生成上下文，也不能被用于直接调参后再当测试集。

## 4. 核心指标

| 指标 | 定义 |
|---|---|
| Repeat consistency | 同一候选多次盲评得到同一选择的比例 |
| Human agreement | 与目标个人、专家或受众选择的一致率和校准 |
| Polish bias | 只改变完成度时，Judge 对 polished 版本的额外偏好 |
| Length bias | 控制内容后，长度对胜率的边际影响 |
| Self-family bias | Judge 对自身模型家族输出的偏好差 |
| Frontier suppression | 被 Judge 淘汰、后来却产生高价值后代的候选比例 |
| Disagreement value | 高 Judge 分歧候选后来进入 Pareto 前沿的概率 |
| Execution correlation | Judge 分数与真实执行结果的相关性及置信区间 |
| Cluster contraction | 每轮选择后结构簇数量的下降速度 |

对单次选择准确率的追求不能牺牲 `Frontier suppression` 和 `Disagreement value`。

## 5. 评估流程

1. **硬门槛：** 事实、版权近邻、安全和不可妥协约束；
2. **独立 critics：** 新颖、结构、受众、执行分别评分，不互看；
3. **分歧路由：** 高质量且高分歧的候选进入人审；
4. **人类决策：** `keep / reject / interesting_uncertain`，同时保存理由；
5. **私有修订：** 生成分支只看针对自身的批评；
6. **现实测试：** 少量 Pareto 候选进入执行；
7. **回写：** 现实结果更新 Judge 校准，但不直接抹掉少数生态位。

## 6. 迭代停止规则

满足任一条件即停止当前路线的继续润色：

- 连续两轮新增结构簇 < 5%；
- 质量增益小于预注册最小效果；
- cluster contraction 超过阈值；
- Judge 分数上升但人评或执行预测下降；
- 主要修改只发生在措辞、格式和解释长度；
- 成本超过同等前沿增量的替代策略。

停止不是删除。高分歧或产生过有价值后代的节点进入开放档案。

## 7. 不要错误解读“小 Judge 胜过大 Judge”

[Recipes for Creativity](https://arxiv.org/html/2608.07243v1)在特定食谱生成 pilot 中发现，较小的循环内选择模型产生了更高的 TTCT 风格分数。可接受的推论是：

> Judge 的归纳偏好比参数规模更重要，必须把 Judge 当作可消融组件。

不可接受的推论是“小模型普遍比大模型更适合判断创意”。生产系统应比较多种 Judge、规则、人类和现实结果，并报告它们的分歧。

## 8. 上线门槛

一个 Judge 只有满足以下条件才可以进入循环内选择：

- 在目标域有盲化审计集；
- 重复一致性和人类一致性达到预注册门槛；
- 长度、润色和自模型偏差已量化；
- 不单独删除 `interesting_uncertain`；
- 与现实结果至少无显著负相关；
- 每个季度或模型升级后重新审计。

LLM Judge 可以筛选和诊断，但不能单独决定 FrontierOS 的冠军。
