# Human Taste Protocol：把人的品味变成方向感，而不是审美牢笼

**版本：** 0.2  
**原则：** 人类提供价值方向、生活异质性和对异常的敏感；AI 扩张搜索、保存谱系、计算不确定性并执行验证。品味模型的职责是提高判断杠杆，不是复制用户过去的平均偏好。

## 1. 三层品味模型

| 层 | 存什么 | 更新速度 | 典型证据 | 作用 |
|---|---|---:|---|---|
| TasteCore | 价值、声音、伦理边界、长期厌恶、不可妥协项 | 慢 | 跨项目重复选择 + 明确理由 + 人确认 | 设置方向与硬边界 |
| TasteContext | 当前项目、受众、媒介、阶段、商业约束 | 快 | 本项目选择、上线数据、当前 brief | 局部排序与取舍 |
| TasteFrontier | 惊奇、矛盾、陌生但有吸引力、尚不能解释的方向 | 不收敛 | 高分歧、高潜力、`interesting_uncertain` | 防止过拟合过去的自己 |

任何单次选择默认只进入 Context 或待确认队列，不自动写入 Core。Frontier 项不得因置信度低而降权；其价值恰恰是保留尚未形成语言的偏好。

## 2. 最小反馈动作

每次只让人完成 15–60 秒的高信息量判断：

1. `keep`：值得推进；
2. `reject`：不值得推进；
3. `interesting_uncertain`：暂时不确定，但含有应保留的东西；
4. 二选一：A/B 更接近目标；
5. 局部标记：具体喜欢或反感哪一处；
6. 原因标签：结构、张力、节奏、惊奇、真实性、伦理、受众、可执行性等；
7. 自由解释：一到三句话，不要求完整理论。

`interesting_uncertain` 必须作为独立类别存储，不能映射成 0.5 分。

## 3. 多裁判，不盲目平均

候选至少保留四组分离判断：

- `personal`：创作者本人的价值、声音和欲望；
- `expert/community`：专业标准、目标群体和文化语境；
- `real_world`：读者行为、市场、原型或实验结果；
- `anti_consensus`：专门检查共识是否过早、少数路线是否被抹掉。

不把四者直接平均。当它们冲突时，记录冲突并路由：商业交付可以提高 Context/real-world 权重；长期原创项目可以保留 personal/frontier 优先；事实、安全和法律约束仍是硬门槛。

## 4. 主动提问策略

只在以下候选上请求人判断：

- 自动 Judge 高分歧；
- 预测“高质量 + 高不确定”；
- 位于新 Pareto 区域；
- 与 TasteCore 冲突但有高执行潜力；
- 来自新模型、语言、文化或机制谱系；
- `interesting_uncertain` 到达复审时间；
- 两个候选的选择会显著改变后续搜索方向。

不请求判断：明显违反硬约束、重复近邻、所有 Judge 都低分且无新结构、只影响措辞而不影响路线的差异。

可用信息价值近似排队：

\[
Priority(x)=Potential(x)\times Uncertainty(x)\times FrontierGain(x) / HumanSeconds(x)
\]

这是调度启发式，不是审美真理。

## 5. 从反馈到资产的路由

| 反馈 | 写入位置 | 条件 |
|---|---|---|
| “任何项目都不要这样做” | TasteCore 候选 | 跨项目复现，且用户明确确认 |
| “这个受众需要更直接” | TasteContext | 只绑定项目/受众 |
| “这个奇怪，但别删” | TasteFrontier + 档案 | 保留原因与复审日期 |
| “这个转折方法有效” | Skill/Operator 实验 | 与算子调用、基线和结果绑定 |
| “事实或设定是……” | 项目记忆/证据库 | 附来源与置信度 |
| 单次无理由点击 | 临时日志 | 不持久化为稳定偏好 |
| 上线后受众反应 | Reality outcome | 区分即时和延迟结果 |

机器可读事件见 [`taste-event.schema.json`](../schemas/taste-event.schema.json)。

## 6. 防止品味过拟合

- 10%–20% 候选绕过个人品味预筛；
- 每个项目至少保留一条反共识岛和一条远距类比岛；
- 训练时分离正偏好、拒绝、兴趣不确定和硬约束；
- 不用单一 Reward 同时拟合“像我”“受欢迎”“正确”“新颖”；
- 对跨时间稳定性做回放测试；旧偏好与新偏好冲突时，不静默覆盖；
- 对模型置信度做校准，低校准时增加人类查询；
- 每季度加入外部策展人或目标受众的盲样，防止自我封闭。

## 7. 低保真介入与 decision locks

在 AI 生成完整成品前，先让人看到：

- 主题矛盾；
- 结构骨架；
- 三种关系类比；
- 关键转折/交互/构图；
- 最有风险的假设；
- 哪些部分由 H0 人类材料驱动。

人可锁定 1–3 个决定：核心矛盾、目标情绪、必须保留的异常、禁止解决的张力。锁定后，Agent 只能在其他维度探索；若要解锁，必须说明现实证据或新机会。

## 8. 评估品味模型

| 指标 | 计算 | 目标含义 |
|---|---|---|
| Pairwise accuracy | 正确预测 A/B 的比例 | 基本排序能力 |
| Brier / ECE | 预测概率与真实选择的校准误差 | 是否知道自己何时不确定 |
| Core stability | 跨项目、跨月的稳定偏好一致性 | 是否捕捉长期品味 |
| Context sensitivity | 项目切换后排序是否合理变化 | 是否避免一个 Soul 套所有任务 |
| Frontier recovery | 未知项后来成为高价值路线的比例 | 是否保护早期异常 |
| Human leverage/min | 每分钟人类反馈带来的前沿增量 | 判断界面的真实效率 |
| Taste diversity | 保留候选在风格/机制/文化来源上的覆盖 | 是否只会讨好一种过去偏好 |

只报告 accuracy 会鼓励模型选择保守多数项。至少同时报告校准、Frontier recovery 和候选多样性。

## 9. 推荐采样节奏

### 冷启动（0–100 个事件）

- 25 个喜欢、25 个不喜欢，逐条标原因；
- 20–40 个跨风格 A/B；
- 至少 10 个 `interesting_uncertain`；
- 暂不训练稳定 Reward，使用检索式案例与规则。

### 成形（100–500 个事件）

- 主动学习优先请求高信息量样本；
- 按领域拆分 Context；
- 训练轻量成对模型或重排器；
- 每 50 个事件做一次时间回放和盲评。

### 成熟（500+ 个可靠事件）

- 可研究多头 Reward/DPO/CRPO，但保留独立维度；
- 使用时间切分和项目留出；
- 每季度人工审计 Core 变更；
- 不删除原始理由，不以模型生成解释替换人的原话。

## 10. 单次评审模板

```yaml
decision: interesting_uncertain
comparison:
  winner: candidate_b
  loser: candidate_a
dimensions:
  quality: 0.72
  meaningful_surprise: 0.91
  voice_alignment: 0.48
  execution_confidence: 0.55
reasons:
  - B 的核心关系第一次看到，但结尾仍然像 AI 在解释主题
  - 不确定受众是否能理解，不要删掉
scope: project
confidence: 0.63
review_after: 2026-09-15
```

最有价值的数据通常不是分数，而是“为什么这个不完善的东西仍值得留下”。
